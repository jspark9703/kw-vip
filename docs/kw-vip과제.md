# 텍스트 명령으로 동작하는 생활보조 로봇

> 
> 
> 
> **공통 환경**: MuJoCo 휠체어–PiPER 모델
> 
> **최종 제출물**: 5분 발표 PPT 및 발표 영상 (성공 및 실패 영상 포함)
> 
> **제출일 및 발표 일정**: 수업에서 별도 안내
> 

## 1. 과제 목표

전동휠체어에 장착된 PiPER 로봇 팔을 MuJoCo에서 제어하여, **사용자가 자연어 텍스트로 동작을 지시했을 때 로봇이 해당 작업을 자율적으로 수행하는 시스템**을 개발합니다. 물리 시뮬레이션에서 동작이 수행되어야 하며, 최종 성능은 반복 시험을 통해 수치로 설명해야 합니다.

본 과제는 거대한 AI 모델을 새로 만드는 프로젝트가 아닙니다. **상황 인식, 명령 해석, 로봇 동작 생성, 물리적 실행, 결과 확인**을 하나의 시스템으로 연결하고, 그 한계를 정량적으로 분석하는 것이 핵심입니다.

### 필수 요구 사항

1. 사용자가 **텍스트 명령을 입력**하면 시스템이 내용을 해석하여 관련 동작을 수행해야 합니다.
2. 로봇의 동작은 제공된 **MuJoCo 휠체어–PiPER 시뮬레이션 환경**에서 실제 관절 및 물리 상태의 변화로 나타나야 합니다. 단순 애니메이션 재생이나 물체 위치 순간이동만으로 과제를 완료한 것으로 인정하지 않습니다.
3. 사람의 지속적인 수동 조작 없이 명령 입력 후 목표 작업을 수행하는 과정을 보여야 합니다. 중간 확인을 요청하는 방식은 허용하되, 어떤 경우에 필요한지 명시해야 합니다.
4. 성공과 실패 사례를 각각 1개 이상 영상으로 기록하고, **반복 평가를 통해 수치화한 결과**를 제시해야 합니다.
5. 최종 **추론은 팀원 각자의 컴퓨터에서 실행**해야 합니다. 외부 서버나 클라우드 API가 행동을 대신 계산하는 구성은 최종 추론으로 인정하지 않습니다.

### 텍스트 명령을 실제로 사용했는지 확인하는 기준

같은 작업에 대한 **서로 다른 표현 2개 이상**을 처리하고, 작업 범위 밖의 명령 또는 수행하면 안 되는 명령에는 부적절하게 움직이지 않아야 합니다. 단 하나의 고정 문구가 들어오면 미리 정해 놓은 관절 궤적을 무조건 재생하는 방식은 텍스트 기반 작업 수행으로 보기 어렵습니다.

예: “3층 버튼을 눌러줘” / “엘리베이터 3층을 선택해 줘” → 같은 작업 수행.  “버튼은 누르지 말고 대기해” / “현재 장면에 없는 7층 버튼을 눌러줘” → 움직이지 않거나 수행 불가를 알림.

## 2. 공통 시작 환경

모든 학생에게 **`wheelchair_piper_lite.xml`** 파일을 제공합니다. 이 모델은 외부 메쉬 없이 구성된 간소화 휠체어, 6축 PiPER, 2개의 카메라, 움직이는 엘리베이터 버튼, 테이블과 큐브를 포함합니다.

wheelchair_piper_lite.xml

| 제공 요소 | 학생이 활용할 수 있는 내용 |
| --- | --- |
| 고정 휠체어와 PiPER | 6개 팔 관절 및 그리퍼 제어, 목표점 도달, 접촉 과제 |
| `head_rgb`, `wrist_rgb` | 이미지 기반 관찰과 목표 인식 |
| `elevator_button_3`, `button_3_slide` | 버튼 누르기 및 실제 눌림 변위 기반 성공 판단 |
| `object_cube`, `side_table` | 물체 집기 및 지정 위치로 이동하기 |
| `ee_site`, `button_target` | 끝점 위치, 목표 위치, 역기구학 실습 |

**모델 범위에 대한 주의:** 휠체어는 고정되어 주행할 수 없고, 버튼은 현재 하나이며 표면에 숫자 3이 그려져 있지 않습니다. 시각화용 팔 링크의 충돌도 비활성화되어 있어, 현재 모델만으로는 팔 전체의 충돌 안전성을 평가할 수 없습니다. 원하는 실험을 위해 버튼·라벨·물체·목표 영역·카메라·충돌 모델을 수정하거나 추가할 수 있으며, **변경한 내용은 발표에서 설명**해야 합니다.

## 3. 시나리오 선택

다음 중 **최소 한 가지 과제를 선택하여 완성**합니다. 여러 과제를 통합하거나 새 시나리오를 제안해도 됩니다.

| 시나리오 | 기본 과제 | 발전 방향 |
| --- | --- | --- |
| **A. 엘리베이터 버튼 누르기** | 텍스트 명령에 따라 목표 버튼에 접근하고 실제로 누르기 | 버튼 숫자 표기, 복수 버튼, 새로운 패널 위치, 명령 거부 |
| **B. 물체 집어서 옮기기** | 텍스트 명령에 따라 큐브를 들어 미리 정한 목표 영역에 놓기 | 물체 초기 위치 변화, 여러 목표 위치, 물체 종류 변화 |
| **C. 자유 생활보조 동작** | 동일한 휠체어–PiPER 모델을 활용한 물리적 조작 동작 | 여러 단계의 행동 연결, 명령 재질문 및 실패 복구 |

.

## 4. 기술 선택은 자유

VLA 사용은 **권장되는 선택지 중 하나이지 필수 조건은 아닙니다.** 개발 목표와 자신의 컴퓨터 사양에 맞춰 다음 중 적절한 방법을 채택합니다.

- **전통적 제어:** 텍스트 명령 해석 → 목표 선택 → IK·경로·관절 제어
- **VLM과 로봇 제어의 결합:** 이미지와 텍스트로 목표를 찾고, 기존 제어 모듈로 작업 실행
- **모방학습:** 시연 데이터로 ACT 등 행동 정책을 학습하고, 텍스트 명령을 행동 선택에 연결
- **소형 VLA:** SmolVLA 등 언어 조건부 행동 모델을 파인튜닝하고 로컬에서 추론
- **하이브리드:** VLA가 작업 목표나 동작을 예측하고, IK·상태 기계 등으로 실행을 제어

## 5. 개발 및 컴퓨팅 환경

| 단계 | 수행 환경 | 지침 |
| --- | --- | --- |
| **시뮬레이션과 학습 데이터 생성** | **각자 컴퓨터** | MuJoCo 실행, 시연 기록, 장면 변화, 데이터 저장 |
| **모델 학습** | **연구실 RTX 4070 Ti 서버 / 새빛관 103호 / 개인 GPU 컴퓨터** | 자원에 맞는 모델·배치 크기·학습 시간을 선택 |
| **최종 추론 및 시연** | **각자 컴퓨터** | 체크포인트를 가져와 로컬에서 명령 입력부터 로봇 동작까지 실행 |

GPU가 없는 경우에는 CPU에서 가능한 경량 모델 또는 전통적 제어·하이브리드 구성을 선택할 수 있습니다. 연구실 서버는 학습용 자원이며, **서버 연결이 끊겨도 최종 데모가 실행되어야 합니다.** 모델 다운로드·학습 단계의 네트워크 사용과 최종 추론의 외부 서버 의존성은 구분합니다.

학습 기반 방법을 사용한 팀은 **시연 에피소드 수, 데이터 생성 방식, 관측 정보(이미지·관절 상태 등), 행동 출력 형식, 훈련 방법과 시간, 체크포인트 크기**를 발표에서 간단히 공개해야 합니다. 학습하지 않은 팀은 이 항목을 ‘해당 없음’으로 표시하고 자신의 제어 방식을 설명하면 됩니다.

## 6. 정량 평가 기준

**성공 장면 한 번만으로 성능을 입증할 수 없습니다.** 작업별 성공 조건을 미리 정의한 후, 동일한 방식으로 반복 평가합니다.

### 6.1 성공 조건 정의

모든 팀은 작업 시작 전에 **성공을 판정하는 측정 가능한 조건**, **시험 종료 조건**, **실패 조건**을 정해야 합니다.

- **버튼 누르기 예시:** 의도한 버튼의 슬라이드 관절 변위가 **10mm 이상**에 도달하면 성공. 관절 변위로 판정하며, 단순히 손끝이 버튼 가까이에 도착하는 것은 성공이 아닙니다. 실제 모델에서 동작 가능한 임계값인지 사전 시험 후 확정합니다.
- **물체 이동 예시:** 큐브를 초기 높이보다 **5cm 이상 들어 올린 뒤**, 지정한 목표 영역 중심에서 **6cm 이내**에 내려놓고 그리퍼를 놓으면 성공. 물체를 코드로 순간이동시키는 것은 제외합니다.
- **실패 예시:** 목표 미달, 다른 작업 수행, 제한 시간 초과, 물체 낙하, 조작 중 비정상 종료 등. 각 팀이 시험 전에 기록합니다.

위 거리와 기준은 **수업 공통화를 위한 권장 예시값**입니다. 모델별 접촉 동작이 확인되면 교수자가 공통 기준을 확정합니다.

### 6.2 최소 20회 반복 시험

| 시험 구분 | 횟수 | 구체적인 조건 | 목적 |
| --- | --- | --- | --- |
| **기본 조건 평가** | 10회 | 학습과 같은 조건 범위의 **새로운 초기 상태/난수 시드** | 기본 성공률 확인 |
| **변화 조건 평가** | 10회 | 학습에 포함하지 않은 물체·버튼 위치, 배치 또는 카메라 조건 중 **도달 가능한 변화** | 일반화 성능 확인 |
| **명령 해석 점검** | 별도 5회 | 명령 재표현 2회, 대기·금지 명령 2회, 불가능한 명령 1회 | 텍스트 의미 반영 및 잘못된 행동 방지 |

단, 위치 변화는 **물리적으로 도달 가능한 범위**에서 설계하고, 훈련 데이터와 평가 시험은 동일한 실행 에피소드를 공유해서는 안 됩니다. 난수 시드와 조건을 시험 전에 고정하고, 실패한 결과를 임의로 제외하지 않습니다.

### 6.3 발표에 들어갈 최소 지표

| 지표 | 계산 또는 기록 방식 | 필수 여부 |
| --- | --- | --- |
| **작업 성공률(SR)** | 성공 횟수 ÷ 전체 시도 횟수 × 100(%) | 필수 |
| **기본/변화 조건 성공률** | 기본 10회와 변화 10회를 각각 계산 | 필수 |
| **일반화 격차** | 기본 성공률 − 변화 조건 성공률(퍼센트포인트) | 권장 |
| **명령 적합성** | 명령 해석 점검 5회 중 올바른 실행·거절 비율 | 필수 |
| **작업 수행 시간** | 명령 입력부터 종료까지 걸린 시간(성공 시험 평균 또는 중앙값, 실패·시간초과 별도 표기) | 필수 |
| **실패 유형별 빈도** | 인식 / 명령 해석 / IK·경로 / 접촉·파지 / 시간초과 등 | 필수 |
| **추론 지연 시간** | 모델이 한 번 동작을 예측하는 데 걸린 시간의 평균 또는 중앙값 | AI 모델 사용 팀 필수 |
| **기준선 대비 개선량** | 규칙 기반 또는 단순 IK 대비 성공률 차이(퍼센트포인트) | 권장 |

계산 예: 기본 조건에서 8/10회, 변화 조건에서 5/10회 성공했다면 **기본 성공률 80%, 변화 조건 성공률 50%, 전체 65%, 일반화 격차 30%p**입니다. “80% 성공”만 선택해 발표하면 안 됩니다. 20회는 교육용 최소 시험 수이므로 표본이 작다는 한계도 설명해야 합니다.

모델 추론 시간과 전체 로봇 작업 시간은 다른 값입니다. **추론을 실행한 개인 컴퓨터의 CPU·GPU·메모리**도 발표에서 표시해야 합니다. 제어 방식이 여러 가지라면 가능한 한 같은 시험 조건으로 비교합니다.

### 6.4 실패 분석

실패 영상 역시 보고하여야 하며, 실패 원인을 분석하고 개선 방향을 제시해야 합니다. 예를 들어 “버튼 근처까지 갔으나 누르지 못함”은 목표 인식, 손목 방향, 충돌 기하, 접촉력, 액추에이터 제어 중 어디에서 실패했는지를 설명해야 합니다.

현재 배포 모델은 팔 링크 충돌이 비활성화되어 있으므로 **이 모델만으로 ‘팔 충돌 0회’와 같은 안전성 주장을 해서는 안 됩니다.** 충돌 성능을 평가하려면 별도 충돌 지오메트리를 활성화해야겠습니다.

## 7. 최종 제출

**제출물은 5분 발표 분량의 PPT 파일 1개 및 발표 영상**입니다. 발표 자료에 **성공 영상 1개 이상과 실패 영상 1개 이상을 삽입**하세요. 영상은 가능하면 PPT에 직접 포함하거나 파일 용량이 크면 이메일로 직접 제출바랍니다.
