# kw-vip v3 — 주행 휠체어 + 장애물 우회 + 숫자 버튼 + 피드백 누르기

v2(고정 휠체어, 색 버튼 3개)에서 최종 태스크를 확장했다:
**텍스트 명령 → 휠체어가 엘리베이터까지 주행(장애물 우회) → 패널 앞 도킹 → 숫자 글씨로 버튼 판독 → 피드백 제어로 누르고 눌렸는지 판단.**
일반화 축은 **패널 위치**와 **패널 주위 장애물**이다. v2 경로(ACT 포함)는 `--scene v2` 로 그대로 남아 있다.

## 1. 모델 변경점 (발표에서 설명할 것) — `models/make_scene_v3.py` → `models/scene_v3.xml`

## 2. 시스템 구성

```
텍스트 ─ nlu (rules + 로컬 LLM, scene=v3: 색 매핑 없음, 건물 층 1~6)
  └ mission/fsm.py
     IDLE (wait/reject/clarify: 휠체어·팔 정지)
     STOW_ARM → NAV_TO_LOBBY → FIND_PANEL → DOCK → OBSERVE/READ_DIGITS → APPROACH → PRESS_SERVO → HOLD
              → RETRACT → VERIFY (실패 시 재인식 후 재시도, 최대 3회) → STOW_ARM → DONE
```

| 서브태스크 | 모듈 | 방법 |
|---|---|---|
| 장애물 확인 | `nav/lidar.py`, `nav/grid.py` | 라이다 점 → 5cm 점유격자 누적 → 거리변환(clearance). 휠체어는 반경 0.68m 원으로 근사(제자리 회전도 안전) |
| 우회 | `nav/planner.py`, `nav/follower.py` | A*(8-연결, 장애물 근접 비용) + 직선화 → pure pursuit. 1s 마다 / 경로가 막히면 재계획, 경로 진동 방지(같은 목표의 기존 경로가 유효하고 새 경로가 15% 이상 짧지 않으면 유지). 몸체 윤곽 앞 15cm 안에 점이 있으면 비상정지 → 15cm 후진 → 재계획 |
| 패널 확인 | `perception/panel.py` | head depth 에서 RANSAC 으로 벽(최대 수직 평면) → 벽 앞 4~12cm 튀어나온 덩어리 중 0.26x0.20m 크기 = 패널. (조명 때문에 벽도 저채도·중간 밝기여서 색으로는 구분 불가) |
| 도킹 | `nav/dock.py` | 지도 사전정보(패널 대략 위치)로 대기 지점 → head 로 패널 확인(못 찾으면 좌우 회전 탐색) → 도킹 자세 앞 0.6m → yaw 정렬 → 재인식 → 직선 접근(횡오차 >1cm 면 물러났다 재접근). 앞쪽이 막히면 반대쪽에서 후진 접근 |
| 버튼 인식 | `control/observe.py`, `perception/digits.py` | 손목 카메라 관찰 자세(정면에서 yaw 20°·tilt 15° 비스듬히 0.18m — 정면 원거리는 팔이 닿지 않음) → 손목 depth RANSAC 으로 패널 평면 → **정면화**(평면 위 격자를 카메라에 투영) → depth 가 라벨 면과 일치하는 픽셀 = 버튼 앞면 원 → 라벨을 숫자 템플릿과 NCC → 헝가리안 1:1 배정 |
| 누르기 + 판단 | `control/press_feedback.py` | 2mm 씩 전진하며 매 단계 목표 버튼 변위·다른 버튼 변위·접촉력 확인 (12mm 도달 멈춤 / 다른 버튼 2mm 후퇴 / 힘 60N 초과 후퇴 / 최대 깊이 미접촉 → 재시도). VERIFY = 관찰 자세에서 램프 점등(HSV) **그리고** 변위 최대값 ≥10mm |

### 가정 (발표에서 명시)
- 자기 위치(odometry)는 베이스 관절 값 = 이상적인 주행계 (미끄러짐·누적 오차 없음).
- 지도 사전정보는 '패널이 대략 어디 있는지(명목 위치)'와 건물 층 정보(1~6층)뿐. 실제 패널 위치(±0.6m)·장애물은 센서로 찾는다.
- 라이다는 높이 0.45m 한 평면만 본다. 그보다 낮은 장애물은 못 본다 (장애물은 모두 0.8m 이상).
- 팔 링크는 원본처럼 충돌하지 않는 시각용이다. 팔 전체 충돌 안전성은 평가하지 않는다.
- 버튼 변위 센서(jointpos)는 '엘리베이터가 호출 등록을 알려 준다'는 상태 신호로 쓴다.

## 3. 중간 확인(되묻기)이 필요한 경우 (요구사항 3)
1. 층이 없거나 여러 층을 말했을 때 (`clarify`): "몇 층을 눌러 드릴까요?" — 대화형 모드에서만 되묻고, 답을 받아 실행.
2. 색으로 지시했을 때("파란 버튼"): v3 버튼은 색이 같으므로 `clarify`.
3. 패널에서 요청 층 버튼을 판독하지 못했을 때: 누르지 않고 "패널에서 N층 버튼을 찾지 못했습니다"를 알린 뒤 팔을 접는다 (평가에서는 `digit` 실패).
그 밖의 경우(press 확정)는 명령 입력 후 사람 개입 없이 끝까지 수행한다.
움직이면 안 되는 명령(wait/reject/clarify)은 휠체어·팔 모두 움직이지 않는다. 건물에 없는 층(7층 등)은 주행 전에 거절한다.
