# kw-vip v4 — 아파트 복도 주행 + 현관 도어락 비밀번호 입력

최종 태스크: **"현관문 열어줘" 같은 텍스트 명령 → 전동 휠체어가 아파트 복도를 주행(택배·사람 우회) → 우리 집 현관 도어락 앞에 도킹
→ 키패드 글자를 읽어 키 위치를 찾음 → 미리 등록된 비밀번호 + `#` 를 키마다 피드백 제어로 입력 → 상태 LED 로 열렸는지 판단.**
일반화 축은 **도어락 위치**(문 위치·도어락 높이)와 **도어락 주위 장애물**(택배·사람 2~3개)이다.
v3(엘리베이터 버튼)는 v4 로 교체했다. v2(고정 휠체어·색 버튼 3개, IK/ACT 비교)는 `--scene v2` 로 남아 있다.

## 2. 장면 무작위화 (`sim/world.py`, 시드만으로 재현)

| 조건 | 문 위치(복도 방향) | 도어락 높이 | 도어락 가로 | 장애물 | 출발 |
|---|---|---|---|---|---|
| base | ±0.3m | 1.08~1.14m | 고정 | 2~3개 | ±0.3m, ±15° |
| variation | ±0.6m | 1.02~1.20m | ±3cm | 2~3개 | ±0.5m, ±45° |

- 도어락 높이 범위는 `tests/check_scene_v4.py` 로 정했다: 1.00~1.22m 에서 키 `1235*0#` 이 모두 첫 시도에 입력됨 → 양쪽 2cm 여유.
- 장애물: 첫째는 **도어락 쪽**(도킹 자세 앞 접근로 근처 → 우회해서 들어가야 함), 둘째는 출발→도어락 직선 위, 셋째(있으면) 경로 밖.
  도킹 자리 여유(로봇 반경 + 10cm)와 경로 실행 가능성(GT 격자, 반경 + 5cm)을 검사해 **아예 누르지 못하는 배치는 만들지 않는다**.
- 등록 비밀번호: 시드마다 4~6자리(로봇 설정과 도어락에 같이 등록). 명령 문장에는 숫자가 없다.

## 3. 시스템 구성

```
텍스트 ─ nlu (규칙 안전장치 + 로컬 LLM, nlu/doorlock.py) ─> {"intent": unlock|wait|reject|clarify}
  └ mission/fsm.py
     IDLE (wait/reject/clarify: 휠체어·팔 정지)
     STOW_ARM → NAV_TO_LOBBY → FIND_PANEL → DOCK → OBSERVE/READ_KEYS → (키마다) APPROACH → PRESS ... '#' → VERIFY → STOW_ARM → DONE
```

| 서브태스크 | 모듈 | 방법 |
|---|---|---|
| 장애물 확인 | `nav/lidar.py`, `nav/grid.py` | 라이다 점 → 5cm 점유격자 → 거리변환. 휠체어는 반경 0.68m 원 |
| 우회 | `nav/planner.py`, `nav/follower.py` | A* + 직선화 → pure pursuit, 1s 마다·막히면 재계획, 몸체 윤곽 앞 15cm 비상정지 → 후진 → 재계획 |
| 도어락 확인·도킹 | `perception/panel.py`, `nav/dock.py` | head depth 에서 RANSAC 벽 평면 → 벽 앞 1.2~4.5cm 튀어나온 80×170mm 덩어리 = 도어락. 후보가 여럿이면 지도 사전정보(우리 집 도어락 대략 위치)에 가까운 것, 1.2m 넘게 떨어진 것(이웃집)은 버림. 대기 지점 → 확인 → 도킹 자세 0.6m 앞 → 재인식 → 직선 접근 (앞이 막히면 반대쪽에서 후진) |
| 키 인식 | `control/observe.py`, `perception/digits.py` | 손목 카메라 관찰 자세(키패드 정면에서 yaw 15°·tilt 10°, 12cm) → 손목 depth RANSAC 으로 하우징 앞면(±1cm 만: 2.2cm 뒤 문짝 면 배제) → 정면화(4px/mm) → 라벨 면 depth 일치 픽셀 = 키 → 회색조 NCC(같은 폰트·굵기 템플릿 0~9 * #) → 헝가리안 1:1 |
| 입력·판단 | `control/press_feedback.py` | 키마다 3cm 앞 접근 → 1mm 씩 전진하며 목표 키 변위·다른 키 변위·접촉력 확인(3.0mm 도달 멈춤 / 다른 키 1.5mm 후퇴 / 40N 초과 후퇴) → 떼기. 키 센서 입력 기록으로 매 키 확인: 미접촉이면 재판독 후 그 키 재시도(2회), 다른 키가 입력되면 `*` 로 지우고 처음부터(1회). 끝나면 관찰 자세에서 **LED 초록 + 키 센서 입력 기록 = 비밀번호+#** 둘 다 맞아야 성공 |

### 가정 (발표에서 명시)
- 자기 위치(odometry)는 베이스 관절 값 = 이상적인 주행계.
- 지도 사전정보는 우리 집 도어락의 **대략** 위치(문 ±0.6m 범위의 중심)뿐. 실제 위치·장애물은 센서로 찾는다.
- 등록 비밀번호는 로봇 설정에 저장된 값이다(사용자가 명령으로 말하지 않음).
- 라이다는 높이 0.25m 한 평면만 본다(장애물은 모두 0.36m 이상).
- 팔 링크는 원본처럼 충돌하지 않는 시각용이다(스타일러스·손가락 패드만 충돌).
- 키 변위 센서는 '도어락 키가 눌렸다'는 신호로 쓴다(실제 도어락의 삑 소리·백라이트에 해당).

## 4. 중간 확인(되묻기)과 움직이지 않는 경우 (요구사항 3)
1. 무엇을 할지 모를 때("버튼 눌러줘", 색으로 지시): "현관 도어락에 등록된 비밀번호를 입력할까요?" — 대화형 모드에서 "네" 면 실행.
2. 도어락에서 비밀번호에 필요한 키를 판독하지 못했을 때: 누르지 않고 알린 뒤 팔을 접는다(`digit` 실패).
- 움직이지 않음: 부정·대기(wait), 다른 집 문("옆집", "1204호"), 숫자 비밀번호를 직접 말한 경우(등록값만 입력), 범위 밖 요청(reject).
그 밖의 unlock 은 명령 입력 후 사람 개입 없이 끝까지 수행한다.

개발 중 고친 문제 (발표 '시행착오'로 쓸 수 있음)
- 키가 안 눌림: 문짝 몸체의 '충돌 없음' 기본 클래스가 키에 상속 / 정적 몸체라 하우징-키 충돌이 제외되지 않음 → 키 충돌 명시 + contact exclude.
- 키 변위가 2.6mm 에서 멈춤: PiPER 모델의 관절 마찰(0.3Nm)·약한 손목 서보로 낼 수 있는 힘이 1~2N → 키 스프링 350→180N/m, 명령 깊이 12mm(키 바닥 뒤엔 힘 한도에서 멈춤).
- 글자 판독 33%: 얇은 글자가 카메라 해상도에서 끊김 → 라벨 글자 외곽선(굵게) + 회색조 NCC → 100%.
- 주행 무한 비상정지(대기 지점이 '패널 쪽' 장애물 자리와 겹침) → 대기 지점을 복도 가운데로, 비상정지 뒤 반경 +12cm 계획, 6회 쌓이면 대안 목표.
- 장애물 옆 팽창 영역 안에 갇혀 경로 없음 → 출발 주변 0.6m 안에서 '더 깊이 들어가지 않는' 칸 허용.
- LED 판독 실패(실제로는 열림): head 추정 기준이라 LED 창이 몇 mm 어긋남 → 판독한 '0' 키 기준 + LED 를 가운데에 둔 재확인.
